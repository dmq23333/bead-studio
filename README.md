# 豆间 · 拼豆工作室

照片 → 缩小量化（可选 Ollama 视觉模型识别主体并选色）→ MARD 221 编辑器 → 拼豆图纸。

## 本地启动：复用已有 Ollama

保留你原来的 `ollama-compose.yaml`，启动并下载视觉模型：

```bash
docker compose -f ollama-compose.yaml up -d
docker exec -it ollama ollama pull granite3.2-vision
```

在本项目目录启动 Python 后端（Python 3.10+，无需 pip 依赖）：

```bash
python server.py
```

打开 http://localhost:8080 。后端默认访问 http://localhost:11434；可用 `OLLAMA_URL` 环境变量指定其他可信 Ollama 服务。不要与下方整套 compose 同时启动两个 Ollama 容器。

## 整套 Docker 启动

```bash
docker compose up --build -d
docker compose exec ollama ollama pull granite3.2-vision
```

访问 http://localhost:8080 。app 通过 Docker 服务名 `http://ollama:11434` 调用 Ollama。默认 CPU，GPU 加速需按你的系统配置。模型首次下载和加载需要时间，推理速度受内存、模型、硬件影响。

## AI 简化网格

1. 上传照片，左侧展开的 AI 区域填写视觉模型名称。
2. 选择 AI 网格宽度 16 / 24 / 32，填写创作要求，如“保留猫咪头像和额头花纹，去掉背景”。高度按比例计算并限制在 8–32 格。
3. 上方“最多颜色”控制配色；AI 最多使用 16 色，至少 2 色。
4. 点击“AI 生成简化网格”：
   - 前端缩小图片，统计图中实际出现最多的 24 个 MARD 色作为候选。
   - 后端调用一次 Ollama，由模型识别主体和特征，并从候选色中选出最终配色。
   - 前端按选定颜色量化缩小后的图片，生成网格。透明、去背景、平滑等设置与普通转换一致。
5. 后端校验色号都在候选内且数量不超限，通过后替换画布。失败保留当前图纸。生成期间若编辑画布或换图，过期结果不会覆盖当前作品。
6. 继续画笔修整并导出。

网格由原图缩小量化得到，构图忠于原图，模型只影响主体说明和配色。模型必须支持图片输入与 Ollama 结构化 JSON 输出，上下文需放得下提示词和图片。默认模型只是可替换示例。

单次模型调用最多等待 240 秒；浏览器最多等待 510 秒。服务一次处理一个 AI 任务。请求超时后服务端可能仍等候当前推理结束；稍后再试。模型错误、尺寸错误、未知色号及全空结果均不会悄悄回退为普通转换。

官方接口参考：https://docs.ollama.com/api/chat
结构化输出：https://docs.ollama.com/capabilities/structured-outputs

## 普通转换与编辑

“普通像素转换”仍可离线使用：平滑采样、Lab 色差匹配、限制颜色数量、邻域杂点清理。它不使用 AI。

- PNG/JPG/WebP，最大 15 MB，保留透明空位。
- 普通转换只有 52×52（默认，1 块板）和 104×104（2×2 块板）两种尺寸，非正方形图片居中放入，空出部分为空位；近白背景去除为阈值方法，会同时移除主体近白区域。
- 转换流程：取原图像素投票，不做平均；选色兼顾覆盖率和色差，眼睛、描边等小面积高对比色不会被渐变挤掉；清理只替换没有同色邻居的相近色杂点，并合并占比低于 1% 的相近色。阈值在 `dist/core.mjs` 顶部。“照片降噪”为可选中值滤波，默认关闭。
- 分割线：52 × 52 上下左右各留一排，中间 50 × 50 按 5 × 5 分块；104 × 104 按每块板重复，其他尺寸每 5 格一条。画布、PNG、打印一致。
- 画笔、填充、橡皮、取色，40 步撤销/重做。填充只改相连的同色区域或空白。
- 垫图重画：把当前图纸淡显为底图（透明度可调），在同尺寸的空白图层上手绘；取色可吸底图颜色。统计、保存和导出只包含手绘层。再点一次退出：有手绘则保留手绘（撤销一步恢复原图），没画则恢复原图。生成新图、换色卡或导入图纸会清空编辑历史。
- 点击目标色，再右键旧色可全局替换。
- 配色清单默认只显示已用颜色；取消勾选可浏览 221 色，支持搜索色号。
- 自定义色卡 JSON：`[{"code":"A1","hex":"#FAF5CD"}]`。AI 生成固定使用内置 MARD 221。旧图纸带有旧色值时，点击“恢复 MARD 221 色卡”，221 色 MARD 图纸会保留原色号并更新显示颜色；其他自定义色卡仍按相近颜色转换。
- 色号图纸、彩色网格、PNG、按 52×52 格一块板分页打印 PDF 及每板用量。

## 二维图纸数据

新保存格式为 v2，每格直接存色号或 null。完整文件含 width、height、palette、cells，以下只演示 cells 的结构：

```json
[
  [null, "A1", null],
  ["H6", "A1", "H6"]
]
```

`cells[y][x]`，null 是不放豆子的空位，白色色号是实际白豆。文件带颜色 HEX，便于独立重绘。导入校验行列数与色号，并兼容旧版 v1 扁平索引文件。编辑器内部使用扁平索引提高绘制效率，保存时转二维色号数组。刷新不会自动保存，请下载项目 JSON。

## MARD 221 色卡来源

`dist/mard221.json` 收录 221 个唯一色号，分 A/B/C/D/E/F/G/H/M 系列；`mard221.mjs` 是相同数据的浏览器模块。

本项目以用户提供的 `mard221.json` 为唯一基准，原样保留 221 条 code、hex、rgb 数据。前端色卡、普通图像转换、Ollama 配色提示与导出共享这套数据。来源标识与文件 SHA-256 校验值见 `dist/palette-source.json`。

与先前社区色卡相比修正了 77 个 HEX 色值。配色清单改用无高光的纯色色块，悬停可查看 HEX。屏幕仍可能存在显示差异，但程序不会再混用其他来源的色值。

## 在线版与隐私

在线托管版是静态前端，提供普通转换、MARD 色卡和编辑导出，不能访问你本机 Ollama。检测不到 Python 后端时 AI 按钮禁用，并显示本地运行说明。点击 AI 时，照片会发送给本地后端，再发送给 OLLAMA_URL 指定的服务；普通转换不上传图片。

## 文件结构

- `dist/`：无构建依赖的网页、图像算法、MARD 色卡。
- `ai_grid.py`：选色提示、JSON Schema、配色校验。
- `server.py`：静态网页、AI 状态和请求代理。
- `Dockerfile`、`compose.yaml`：本地部署。
- `tests/`：前端算法与后端集成测试。

本版本默认使用方格图，逐格绘制横竖网格线，按上文分割线规则加粗，空位保留空白格。色号视图在同一网格上叠加色号，PNG 导出同样使用网格。
